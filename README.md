# Apply Agent

أداة بتدوّر على وظايف الـ AI Engineering من غيري ما أفتح موقع، بتقيّمها على سيرتي، وبتجهّز التقديم.

المشروع بيتبني على **4 مراحل**. المرحلة اللي شغالة دلوقتي هي **1** بس.

---

## المرحلة 1 — سحب الوظايف (اللي في الريبو ده)

### بتعمل إيه بالظبط

كل نص ساعة، البرنامج بيعدّي على قايمة شركات، بيسحب وظايفهم، وبيحفظ **الجديد بس** في Supabase.

```
companies.yaml  →  الـ adapters  →  توحيد الشكل  →  بصمة  →  Supabase
   (السجل)         (سحب)            (Job)          (منع     (جدول jobs)
                                                    التكرار)
```

### مش بتعمل إيه

- **مفيش AI.** التقييم في المرحلة 2.
- **مفيش تليجرام.** في المرحلة 3.
- **مفيش تقديم.** ده إنت.
- **مبتلمسش LinkedIn خالص.** وده مقصود — الـ APIs دي بتديك الوظيفة ساعة ما تتنشر، قبل ما توصل LinkedIn وقبل ما الـ 100 متقدم يتجمعوا.

### ليه الطريقة دي مسموحة

معظم الشركات بتستخدم نظام توظيف جاهز (Greenhouse أو Lever أو Ashby أو Recruitee)، وكل واحد فيهم عنده **رابط عام موثّق** بيرجّع الوظايف كـ JSON. ده نفس الرابط اللي موقع الشركة نفسه بيستخدمه. مفيش scraping ومفيش تسجيل دخول ومفيش أي حاجة ممنوعة.

## التشغيل — 5 خطوات

### 1. البيئة

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

### 2. الداتابيز

في Supabase → **SQL Editor** → الصق محتوى `sql/002_slice1.sql` → Run.

بيعمل جدولين: `jobs` (الوظايف) و`agent_runs` (سجل كل تشغيلة لأي مكوّن).

### 3. المفاتيح

```bash
copy .env.example .env
```

وبعدين افتح `.env` وحط `SUPABASE_URL` و`SUPABASE_SERVICE_KEY` من
Supabase → Project Settings → API.

> **مهم:** `service_role` مش `anon`. ده مفتاح بيتخطى الـ RLS، فمكانه `.env` و GitHub Secrets بس. ملف `.env` أصلاً في `.gitignore`.

### 4. اتأكد من السجل

```bash
python -m src.main --verify
```

هيقولك كل شركة رجّعت كام وظيفة. الشركات اللي بترجّع **صفر** يبقى الـ token بتاعها غلط.

**ازاي تجيب الـ token الصح:**
1. افتح صفحة التوظيف بتاعة الشركة
2. `F12` → تاب **Network** → اعمل refresh
3. دوّر على نداء فيه `greenhouse` أو `lever` أو `ashby` أو `recruitee`
4. الـ token هو الجزء اللي بعد اسم النظام في اللينك

### 5. أول سحبة حقيقية

```bash
python -m src.main --dry-run    # شوف الأول من غير حفظ
python -m src.main              # احفظ
```

## النشر على GitHub Actions — مجاني

الفايدة إنه بيشتغل **والجهاز مقفول**.

1. ارفع الريبو على GitHub
2. Settings → Secrets and variables → **Actions** → New repository secret:
   - `SUPABASE_URL`
   - `SUPABASE_SERVICE_KEY`
3. تاب **Actions** → `Poll jobs` → **Run workflow** عشان تجرّبه فورًا

بعد كده بيشتغل لوحده كل نص ساعة.

**تلات حاجات تعرفها:**
- الريبو **public** = دقايق غير محدودة. private = 2,000 دقيقة في الشهر، ومش هتكفي للتشغيل كل نص ساعة.
- GitHub ممكن **يأخّر** التشغيل 5–15 دقيقة وقت الضغط.
- بيوقّف الـ schedule لو الريبو مفيهوش نشاط **60 يوم**. commit واحد كل شهرين بيحلها.

## فكرة البصمة (`content_hash`)

المشكلة: الشركة بتشيل وظيفة وتعيد نشرها برقم جديد، فتوصلك تاني كإنها جديدة.

الحل: البصمة مش على الرقم — على **اسم الشركة + عنوان الوظيفة + الموقع + الوصف** بعد تطبيعهم (حروف صغيرة، مسافات موحّدة). والعمود `unique` في الداتابيز، فالتكرار مستحيل حتى لو حصل خطأ في الكود.

## المراحل الجاية

| المرحلة | بتعمل إيه | بتوفر إيه |
|---|---|---|
| **2** | تقييم بالـ LLM + نداء تاني بيخاصم التقييم الأول | مراجعة الوظايف — 10 دقايق/يوم |
| **3** | CV مظبوط لكل وظيفة + رسالة recruiter + تليجرام | التظبيط — 25 دقيقة/يوم |
| **4** | قياس: هل التقييم توقّع الردود فعلاً؟ | لا حاجة — دي للـ CV بتاعك |

المرحلة 4 هي أهم واحدة مهنيًا: بعد ~6 أسابيع هيبقى عندك ~120 وظيفة متقيّمة و~60 تقديم بنتايج معروفة. ده **ground truth** حقيقي تقدر تقيس عليه، وهي الحاجة اللي كل مشروع جانبي بيفتقدها.

## دعوات LinkedIn

بتشتغل **على جهازك** مش على GitHub — محتاجة جلسة LinkedIn بتاعتك،
وحطّ جلسة زي دي على سيرفر معناه إن اللي يوصل للسيرفر يوصل لحسابك.

```bash
python -m src.connect --login
```

بيفتح متصفح. سجّل دخولك بإيدك مرة واحدة — الكود مش بيلمس بياناتك
ولا بيخزّنها. الجلسة بتفضل في `~/.apply-agent/linkedin-profile`.

```bash
python -m src.connect          # معاينة: مين هيتبعتله
python -m src.connect --send   # ابعت فعلاً
python -m src.connect --stats  # الاستهلاك
```

**ثلاث ضمانات في ثلاث طبقات:**

| الطبقة | الضمانة |
|---|---|
| الداتابيز | قيد `unique` على الرابط — مستحيل يتبعت لنفس الشخص مرتين |
| الكود | ميزانية أسبوعية ويومية بتتحسب من التاريخ الفعلي |
| المتصفح | أي علامة اعتراض من LinkedIn ← وقف فوري وقفل الجلسة |

الافتراضي **معاينة** مش إرسال. الدعوة فعل ما بيترجعش.

للتشغيل التلقائي: Task Scheduler كل ساعتين مع `--send`.

### التشغيل التلقائي (Windows)

```bash
powershell -ExecutionPolicy Bypass -File scripts\install-task.ps1
```

بتسجّل مهمة في Task Scheduler: **4 مرات في اليوم + تأخير عشوائي لحد 40 دقيقة.**

التأخير العشوائي مقصود — التشغيل الساعة 9:00 بالظبط كل يوم إيقاع آلة.

السجل في `logs/connect.log`. للإيقاف:

```bash
powershell -Command "Disable-ScheduledTask -TaskName ApplyAgent-LinkedIn"
```

> ملحوظة: السكريبت بيقف **قبل** ما يفتح المتصفح لو الميزانية خلصت،
> فالتشغيلات الزيادة بتخلص في ثانية من غير أي أثر.
